# Cost model for the pre-registered runs (models, prices, tokens, GPU-hours)

Written 18 Oct 2026 from the reader reports `docs/reads/models-cost.md` (prices, model cards,
throughput, the reader's own cost model), `data-locomo.md` and `data-longmemeval.md` (dataset volumes)
and `baselines-code.md` (what the baseline gates actually call). Every price and fact carries the
reader's flag: "(verified)" means the reader read it from the cited primary page on 18 Oct 2026, or,
where a file is named, that the file on disk (`paper2/llm.py`,
`data/raw/longmemeval/longmemeval_s_cleaned.json`) shows it as read or counted on 18 Oct 2026;
"(VERIFY)" means the reader marked it unverified, derived it from an assumption, or did not cover it.
Every dollar and GPU-hour figure in sections 4–5 is a derivation from stated assumptions, never a
measurement; nothing here comes from `paper2/out`. The pre-registration's phrase "LLM-free" refers to the
write-path decision only; the costs below are what the pipeline around the gate costs.

at temperature 0, `max_tokens=10`, label = "yes" in the lowercased response, with the paper's reported

uses `gpt-4o-mini` at temperature 0 in JSON mode with a lenient prompt (verified; `data-locomo.md`), and

model family from the gate to avoid self-preference, and running the canonical gpt-4o judge at least

### 2.4 Memory-R1-style learned gate

Memory-R1 trained its manager with PPO/GRPO in VERL on 4x H100 80GB (8 for the 14B backbone), batch
128, on 152 LoCoMo training QA pairs (verified); the official repository has no code ("Code coming
soon") and the only public reproduction reports near-zero manager reward (verified). On one 24 GB GPU
the options are LoRA-GRPO on `Qwen3-4B-Instruct-2507` (a different baseline, which must be disclosed) or
renting 4x H100 SXM at $2.69/h community (verified price); the number of training hours is not
estimated anywhere (VERIFY). The pre-registration already marks this policy optional.

## 6. Determinism, seeds and the temperature question

- The pre-registration asks for temperature 0 for the extractor and the answerer and defines the three
  extraction seeds as sampling at temperature 0.3. On the local route this is directly expressible:
  `OpenAICompatClient` sends `temperature` to the server, and Qwen's cards document greedy and sampled
  decoding (verified). The models reader notes that three "seeds" at temperature 0 with a deterministic
  model are meaningless and that seeds must be defined as sampling above 0 or as extractor variants (LLM
  vs GLiNER2 vs spaCy), otherwise reviewers will flag it.
- On the Claude route the models reader's report gives no statement about temperature. The project's
  own adapter does: the `AnthropicClient` docstring in `paper2/llm.py` (read 18 Oct 2026) states that
  Claude Opus 5.5, Claude Fable 5.1 and Claude Haiku 5.5 "run adaptive thinking that cannot be
  disabled" and that "the Messages API offers no temperature / top_p / top_k control under thinking";
  depth is steered only by `output_config.effort`, and the client sends `thinking={"type": "adaptive"}`
  and `output_config.effort` and no temperature (verified on disk; consistent with critique A6.5 and
  with section C recommendation 5, "with a thinking model the repeats are not controlled by temperature
  at all"). Haiku 5.5's default effort is medium (verified). The docstring does not name
  `claude-sonnet-5-5`, so the same statement for Sonnet 5.5 has no project source (VERIFY). Consequence:
  temperature-based extraction seeds and the H2 repeats (critique C5 asks for temperature 0.7) cannot
  be done on Claude; on the Anthropic client `seed` and `repeat` separate the cache entries, so repeats
  are genuinely repeated requests, but nothing in the request pins the sample (docstring). The extractor
  and answerer therefore belong on the local route, with Claude limited to the gate baseline and the
  judge-at-scale, which is what the module docstring itself prescribes.
- The official LongMemEval judge is deterministic by construction (temperature 0, `max_tokens=10`,
  verified), as is Mem0's judge (temperature 0, verified). Mem0's gate as shipped runs at temperature 0.1
  (verified), so a "verbatim" Mem0 gate is not deterministic unless that default is overridden and the
  override is declared.
- Cache keys: `llm.py` (`CachedClient.cache_key_for`, read 18 Oct 2026) hashes the namespace, the model,
  the temperature (`'default'` on the Anthropic client, the float on the local one), the effective seed
  (per-call or client-wide), the repeat index, the system prompt, the prompt, the caller's `cache_key`
  and `max_tokens`. The namespaces are `anthropic:<model>:<effort>:temp=default` and
  `local:<model>:temp=<t>`; `_parse_local_spec` reads the optional trailing temperature of a
  `local:<base_url>:<model>[:<temperature>]` spec and `make_client` passes it to `OpenAICompatClient`.
  The `cache_key` built in `run.py` for answers contains conversation, question, policy and gate
  description. Critique A6.6 (three seeds collapse into one cached answer) is therefore closed in code,
  as `05-critique-response.md` item 8 states (verified on disk), and the cost lines above, which assume
  the repeats are real calls, hold. What the key cannot do is pin the sample on the Anthropic client
  (previous bullet).

## 7. Judge choice and comparability

- LongMemEval-S: run `evaluate_qa.py`'s six verbatim prompts with `gpt-4o-2024-08-06` (verified) on
  every policy's answers; report both Overall Accuracy and Task-averaged Accuracy and say which is
  primary; abstention items are also counted inside their type bins (verified). Budget $10–$14 for the
  grid (section 4, line D). A Haiku 5.5 judge on the same 9,000 calls would cost about $0.40 but is not
  the official metric and shares a family with a Haiku gate; if used as a second judge, report agreement
  with gpt-4o.
- LoCoMo: the official metric is Porter-stemmed token F1 with the comma-split multi-hop rule and the
  two-substring adversarial check (verified; vendored per `05-critique-response.md` item 7); no judge
  cost. A Mem0-compatible "J" with `gpt-4o-mini` is optional and must be labelled by the Mem0 category
  convention when compared with Mem0's table. `data-locomo.md` lists five integer-to-name conventions;
  of these the official mapping (`evaluation.py`, ACL Table 5), Zep's per-category integers recomputed
  from its released grades file and the Memobase fork's explicit category list in code are verified,
  while the assignments attributed to Mem0, Hindsight, Memory-R1, MemoryOS and the Memobase "Zep*" row
  are the reader's inferences from reproduced weighted means and relabelled tables (VERIFY). LoCoMo_refined reports the lenient judge agrees with humans 43.67% of the time
  against 86.33% for a strict judge (verified), which is the argument for F1 plus the official LongMemEval
  judge rather than a lenient judge on both datasets.
- Pin model snapshots in every result file (Kumiho's 0.565 to 0.531 change came from an unpinned gpt-4o,
  verified).
