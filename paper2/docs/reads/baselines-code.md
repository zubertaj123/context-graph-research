1) A-MAC (arXiv 2603.04549, Workday AI; repo GuilinDev/Adaptive_Memory_Admission_Control_LLM_Agents, MIT, 1 commit). Score S(m)=w·[U,C,N,R,T], admit iff S >= theta (scorer.py L174-184). Features as coded: U = one Ollama `qwen2.5:latest` call with a 5-turn context window, prompt asks for a single float in [0,1] (features/utility.py L117-128), fallback 0.5; C = max over "support spans" (every prior turn sharing >=1 lowercase whitespace token with the candidate) of rouge_score ROUGE-L F-measure with use_stemmer=True, 0.0 if no span (confidence.py L44-61, L78-93); N = 1 - max cosine (all-MiniLM-L6-v2), 1.0 when the existing set is empty (novelty.py L47-65); R = exp(-0.01*age_hours) (recency.py L47-54); T = keyword-count argmax over types with priors preference/identity/belief/value 0.9, fact/knowledge/information 0.7, plan/goal/intention/task 0.5, state 0.3, temporary/ephemeral/transient 0.2, unknown 0.5 (type_prior.py L32-85). Critical reimplementation facts: in both experiment scripts N is computed against an empty list (optimize_weights_cv.py L78; run_all_baselines.py L99) so N==1.0 everywhere; R is computed against time.time() while LoCoMo turns get synthetic 2023 timestamps (data_loader.py L109-119), so R~0. Labels: every dialogue turn is a candidate; positive iff its dia_id appears in any QA `evidence` list (data_loader.py L175-199); conversation-level 70/15/15 split seed 42 on locomo10.json (10 conversations); only first 150 train+val candidates and 100 test candidates are used (optimize_weights_cv.py L253-257). Weight learning: candidate set = equal weights + 200 random (uniform(0.05,1) normalized) + five emphasized vectors ([0.1,0.1,0.1,0.1,0.6] permutations) x thresholds {0.3,...,0.6 step 0.05}; 5-fold KFold, objective = mean validation-fold F1 (nothing is fitted on train folds), output results/optimized_weights_cv.json (L119-217). README/paper chosen weights [0.1,0.1,0.1,0.1,0.6], theta=0.55. Reported P/R/F1 0.417/0.972/0.583 is admission-label F1 vs evidence labels (N=225 test in paper), not QA. Missing from repo: data/locomo/data/locomo10.json, results/*.json, the README-referenced WeightOptimizerCV/ConversationTurn/load_locomo_dataset APIs, and the paper's Algorithm-1 conflict merge (sim 0.85).

2) MemoryOS (arXiv 2506.06326, EMNLP 2025; BAI-LAB/MemoryOS, Apache-2.0). Paper: Heat = a*N_visit + b*L_interaction + g*R_recency, a=b=g=1, R_recency=exp(-dt/mu), mu=1e7, dt seconds since last retrieval; promote segment to LPM when Heat > tau=5 then reset L_interaction; STM FIFO length 7; MTM 200 segments; merge when cos+Jaccard >= 0.6. Code (memoryos-pypi/mid_term.py L20-36): HEAT_ALPHA=1.0, HEAT_BETA=1.0, HEAT_GAMMA=1, RECENCY_TAU_HOURS=24, R_recency = exp(-delta_hours/24) via utils.compute_time_decay (utils.py L228-237). Trigger: memoryos.py L25 H_PROFILE_UPDATE_THRESHOLD=5.0; `_trigger_profile_and_knowledge_update_if_needed` (L126-224) peeks the max-heap top, and if heat >= threshold runs two parallel LLM calls (profile analysis, knowledge extraction), writes to LPM, marks pages analyzed, resets N_visit=0 and L_interaction=0, recomputes heat. N_visit only increments inside search_sessions when a page matches (mid_term.py L343-351); L_interaction += pages on merge (L271). Eviction is LFU by access count (L71-101, L176-177), not lowest heat. Eval scripts that produced the LoCoMo numbers use different constants: eval/mid_term_memory.py L24 compute_segment_heat(alpha=0.8, beta=0.8, gamma=0.0001), recency tau=3600 s; eval/main_loco_parse.py: H_THRESHOLD=5.0, ShortTermMemory(max_capacity=1), MidTermMemory(max_capacity=2000), topic_similarity_threshold=0.6, retrieval queue 10, thresholds 0.1, answer LLM gpt-4o-mini T=0.7.

3) Mem0 (mem0ai/mem0). Current main (pyproject 2.2.1) is ADD-only: `_add_to_vector_store` (mem0/memory/main.py L881-1110) retrieves top_k=10 existing memories, makes ONE LLM call with system=ADDITIVE_EXTRACTION_PROMPT and user=generate_additive_extraction_prompt(...), md5-dedups, inserts; get_update_memory_messages is defined (prompts.py L406-461) but no longer called. The classic ADD/UPDATE/DELETE/NONE gate exists through tag v1.0.11 (PyPI 2026-04-06) and is gone in v1.1.0. Classic flow (v1.0.2 main.py L386-600): parse_messages -> system prompt USER_MEMORY_EXTRACTION_PROMPT (AGENT_... when agent_id + assistant msgs; FACT_RETRIEVAL_PROMPT only via legacy helper/custom), user "Input:\n{parsed}", json_object; per fact embed + vector_store.search(limit=5); union, dedupe, map UUIDs to "0","1",...; one LLM call with get_update_memory_messages(old, facts, custom) as a single user message; dispatch on event ADD/UPDATE/DELETE/NONE. FACT_RETRIEVAL_PROMPT and DEFAULT_UPDATE_MEMORY_PROMPT are byte-identical between v1.0.2 and main (verbatim text in facts). LLM defaults: temperature 0.1, top_p 0.1, max_tokens 2000, OpenAI default model gpt-4.1-nano-2025-04-14. Paper names the no-op NOOP and uses s=10, m=10.

4) Memory-R1 (arXiv 2508.19828 v5; ACL 2026 long paper). Official repo yansikuan/memory-r1 contains only README/LICENSE/assets: "Code coming soon". Ops ADD/UPDATE/DELETE/NOOP; reward = exact match of a frozen Answer Agent; Answer Agent retrieves 60 memories (30 per speaker); training data 152/81/1307 QA split (1:1:8) of LoCoMo minus adversarial, no gold operation labels; backbones LLaMA-3.1-8B-Instruct, Qwen-2.5-3B/7B/14B; VERL, PPO lr 1e-6/1e-5, batch 128, prompt 4096/response 2048. A third-party repro (pradyutnair-prosus/memory-r1) exists but reports near-zero MM reward.

5) LightMem (arXiv 2510.18866, ICLR 2026; zjunlp/LightMem, MIT). Filtering: LLMLingua-2 token-classifier compression at rate r (re-compress while >=512 tokens), sensory buffer of 512 user tokens (SenMemBufferManager), coarse topic boundaries = local maxima of sentence-level attention M[i,i-1] from LLMLingua-2 layers [8,9,10,11] with first/last 3 tokens masked, fine boundaries = adjacent-turn cosine (all-MiniLM-L6-v2) below an adaptive threshold starting 0.2 rising 0.05 to 0.5, kept when within +-3 of a coarse boundary; STM buffer hard-coded 512 tokens (lightmem.py L173); one extraction call per triggered batch (METADATA_GENERATE_PROMPT). Accounting: token_stats from provider response.usage per call, split add_memory/update/summarize/embedding; api_call_nums = extraction calls; paper "Total tokens" = summary + update in/out, "Calls" = LLM invocations during construction, "Runtime" = wall-clock construction incl. LLMLingua-2; retrieval/answering excluded; embeddings reported separately. Baselines measured with memory_toolkits/token_monitor.py (monkey-patched LLM calls, litellm tokenizer counts, gpt-4 tokenizer).
